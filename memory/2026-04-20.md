# 2026-04-20 下午：订单导入问题排查与修复

## 问题回顾
1. "Unknown column 'project_name'" 报错 → 已确认 DB 层 orders 表有 `project_name` 列，真实原因是 contracts 查询预加载用了不存在的 `project_name` 列
2. "existing is not defined" → 变量作用域问题
3. 导入超时 → 逐行 DB 查询（3000+ 行串行执行）

## 根本原因
apply_fixes.js 脚本中，`const oldLoop` 的目标是 `for (let i = 1...` 的前一个空行（`\r\n    for`）。但 CRLF 文件中，`split('\n')` 后 `\r` 附在每行末尾，导致字符偏移判断错误。后续多次尝试修复都遇到 CRLF/空格/变量名冲突问题，apply_fixes5.js 和 apply_fixes6.js 成功。

apply_fixes6.js 中 Step2 的 newLoop 模板还包含 `const toCreate/toUpdate` 声明，导致同一变量在两个位置分别用 `let` 和 `const` 声明——重复声明错误。rm_dup.js 修复了这个问题。

### 修改5：阶段二批量写入（~line 492）

```javascript
// 阶段二：批量写入 DB（事务保证原子性，避免超时）
let createdCount = 0, updatedCount = 0;
if (toCreate.length > 0 || toUpdate.length > 0) {
  const t = await sequelize.transaction();
  try {
    if (toCreate.length > 0) {
      const records = toCreate.map(item => item.record);
      const created = await Model.bulkCreate(records, { transaction: t });
      createdCount = created.length;
    }
    if (toUpdate.length > 0) {
      await Promise.all(toUpdate.map(async ({ instance, record }) => {
        await instance.update(record, { transaction: t });
      }));
      updatedCount = toUpdate.length;
    }
    await t.commit();
  } catch (err) {
    await t.rollback();
    throw err;
  }
}
created = createdCount;
updated = updatedCount;
```

## 调试过程教训
- CRLF 文件用 `split('\n')` 时，`\r` 留在每行末尾，用字符串 indexOf 精确匹配容易出错
- 多次修改同一文件时，之前修改会改变后续行号，需要每次都验证
- PowerShell 的 `&&` 在某些上下文中不支持，用 `;` 替代
