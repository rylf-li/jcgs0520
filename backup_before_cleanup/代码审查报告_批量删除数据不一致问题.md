# 代码审查报告 - 批量删除后数据查询超时问题

## 一、问题概述

**问题描述：** 批量删除请款批次、收款管理后，数据查询出现超时，浏览器提示：
- 403 Forbidden 错误
- AxiosError: timeout of 30000ms exceeded
- 多个页面（合同管理、项目管理、订单复核、财务管理）均受影响

**问题根源：** 批量删除操作后的金额重算逻辑不完整，导致数据不一致，进而引起查询超时和权限验证失败。

---

## 二、核心BUG分析

### 【严重BUG-1】批量删除请款批次后缺少合同/项目金额同步

**位置：** `backend/src/routes/paymentRequestBatches.js:87-112`

**问题描述：**
```javascript
async function recalculateOrderPaymentSummary(orderId) {
  // ... 省略部分代码
  
  await order.update({
    requested_amount: requestedAmount,
    received_amount: receivedAmount,
    payment_status: paymentStatus,
    finance_generated: requestedAmount > 0 ? 1 : 0,
    finance_booked: receivedAmount > 0 ? 1 : 0
  });
  
  // ❌ 缺少关键步骤：没有同步合同和项目的金额！
  
  return order;
}
```

**对比正确的实现：**
在 `backend/src/utils/paymentFlow.js:189-251` 的 `recalculateOrderFinancials` 函数中：

```javascript
async function recalculateOrderFinancials(orderId, models, options = {}) {
  // ... 重算订单金额
  
  await order.update({ /* ... */ });
  
  // ✅ 正确实现：同步合同和项目金额
  if (order.contract_id) {
    await syncContractAmount(order.contract_id, models);
    const contract = await Contract.findByPk(order.contract_id);
    if (contract?.project_id) {
      await syncProjectAmount(contract.project_id, models);
    }
  }
  
  return order;
}
```

**影响范围：**
- 批量删除请款批次时，订单的金额会更新，但合同和项目的金额不会更新
- 导致合同管理、项目管理页面显示的金额数据不一致
- 数据库中存在大量"脏数据"，影响查询性能

**修复方案：**
```javascript
async function recalculateOrderPaymentSummary(orderId) {
  if (!orderId) return null;
  const order = await Order.findByPk(orderId);
  if (!order) return null;

  const requests = await PaymentRequest.findAll({
    where: { order_id: orderId },
    attributes: ['request_amount', 'received_amount'],
    raw: true
  });
  
  const requestedAmount = requests.reduce((sum, item) => sum + Number(item.request_amount || 0), 0);
  const receivedAmount = requests.reduce((sum, item) => sum + Number(item.received_amount || 0), 0);
  
  let paymentStatus = '未请款';
  if (requestedAmount > 0 && receivedAmount <= 0) paymentStatus = '已请款';
  if (requestedAmount > 0 && receivedAmount > 0 && receivedAmount < requestedAmount) paymentStatus = '部分收款';
  if (requestedAmount > 0 && receivedAmount >= requestedAmount) paymentStatus = '已收款';

  await order.update({
    requested_amount: Number(requestedAmount.toFixed(2)),
    received_amount: Number(receivedAmount.toFixed(2)),
    payment_status: paymentStatus,
    finance_generated: requestedAmount > 0 ? 1 : 0,
    finance_booked: receivedAmount > 0 ? 1 : 0
  });
  
  // ✅ 新增：同步合同和项目金额
  if (order.contract_id) {
    const { syncContractAmount, syncProjectAmount } = require('../utils/syncAmount');
    await syncContractAmount(order.contract_id, models);
    const contract = await Contract.findByPk(order.contract_id);
    if (contract?.project_id) {
      await syncProjectAmount(contract.project_id, models);
    }
  }
  
  return order;
}
```

### 【严重BUG-3】同步函数性能问题导致超时

**位置：** `backend/src/utils/syncAmount.js:28-97`

**问题1：同步链路过长**
每次删除操作都会触发完整的同步链：
```
订单 → 合同 → 项目
```
批量删除N条记录时，会有N次同步，导致：
- 数据库查询次数过多
- 同步时间随批量大小线性增长
- 容易超过30秒超时限制

**问题2：缺少批量同步优化**
当前实现每次只同步一个合同或项目，批量操作时应优化为：
- 收集所有受影响的合同ID和项目ID
- 去重后批量同步
- 避免重复计算

**修复方案：**
```javascript
// 在批量删除时收集受影响的合同和项目，最后批量同步
router.post('/batch/delete', async (req, res) => {
  try {
    const { ids = [] } = req.body;
    
    const contractIds = new Set();
    const projectIds = new Set();
    
    // ... 执行删除操作，收集受影响的合同和项目ID
    
    // ✅ 批量同步（去重后执行）
    const { syncContractAmount, syncProjectAmount } = require('../utils/syncAmount');
    
    for (const contractId of contractIds) {
      await syncContractAmount(contractId, models);
    }
    
    for (const projectId of projectIds) {
      await syncProjectAmount(projectId, models);
    }
    
    success(res, { /* ... */ });
  } catch (err) {
    fail(res, err.message, 500);
  }
});
```

### 【严重BUG-4】数据库缺少关键索引

**问题：**
以下查询频繁但缺少索引，导致查询性能差：

1. **财务查询：** `Finance.findAll({ where: { contract_id: contractId } })`
   - 缺少索引：`idx_contract_id`
   
2. **请款明细查询：** `PaymentRequest.findAll({ where: { order_id: orderId } })`
   - 缺少索引：`idx_order_id`
   
3. **收款明细查询：** `ReceiptItem.findAll({ where: { payment_request_id: id } })`
   - 缺少索引：`idx_payment_request_id`

4. **权限过滤查询：** 涉及多表关联查询，缺少复合索引

**修复方案：**
执行以下SQL添加索引：


### 【中等BUG-5】403 Forbidden 错误原因

**问题分析：**
403错误通常出现在权限过滤环节，可能原因：

1. **关联数据被删除后，权限过滤查询异常**
   - `applySalesScope` 函数可能查询已删除的业务员数据
   - `buildFinanceSalesScope` 函数可能因关联数据缺失返回异常

2. **数据库中存在"孤儿记录"**
   - 删除操作后，部分记录的 `salesman_id`、`contract_id`、`project_id` 指向了不存在的记录
   - 权限过滤时查询这些关联表会返回null，导致权限验证失败

**排查建议：**
检查数据库中是否存在孤儿记录：

```sql
-- 查找salesman_id指向不存在员工的记录
SELECT * FROM payment_request_batches 
WHERE salesman_id IS NOT NULL 
  AND salesman_id NOT IN (SELECT id FROM employees);

SELECT * FROM receipts 
WHERE salesman_id IS NOT NULL 
  AND salesman_id NOT IN (SELECT id FROM employees);

-- 查找contract_id指向不存在合同的记录
SELECT * FROM finances 
WHERE contract_id IS NOT NULL 
  AND contract_id NOT IN (SELECT id FROM contracts);

-- 查找batch_id指向不存在批次的记录
SELECT * FROM receipts 
WHERE batch_id IS NOT NULL 
  AND batch_id NOT IN (SELECT id FROM payment_request_batches);
```

**修复方案：**
1. 清理孤儿记录或设置关联字段为NULL
2. 在删除操作时，增加关联数据的清理逻辑
3. 在权限过滤函数中，增加对null和不存在记录的容错处理

## 三、性能优化建议

### 1. 前端超时配置优化

**当前：** 30秒超时
**建议：** 根据操作类型动态调整

```javascript
// frontend/src/utils/request.js
import axios from 'axios'

const request = axios.create({
  baseURL: '/api',
  timeout: 30000, // 默认30秒
})

// 对于批量操作，使用更长的超时时间
export const batchRequest = axios.create({
  baseURL: '/api',
  timeout: 120000, // 批量操作120秒
})
```

### 2. 后端查询性能优化

**优化点：**
1. 使用分页查询，避免一次性加载大量数据
2. 使用数据库聚合函数，减少应用层计算
3. 缓存常用查询结果（如权限范围）

**示例：**
```javascript
// 优化前：全量查询后在应用层计算
const orders = await Order.findAll({ where: { contract_id: contractId } });
const total = orders.reduce((sum, o) => sum + Number(o.total || 0), 0);

// 优化后：使用数据库聚合
const result = await Order.findOne({
  where: { contract_id: contractId },
  attributes: [[fn('SUM', col('total')), 'total']],
  raw: true
});
const total = Number(result.total) || 0;
```

### 3. 异步处理批量操作

**建议：** 将批量删除改为异步任务

```javascript
// 创建异步任务
router.post('/batch/delete', async (req, res) => {
  const taskId = await createAsyncTask('batch_delete_payment_requests', req.body);
  
  // 立即返回任务ID
  success(res, { taskId, status: 'pending' });
});

// 查询任务进度
router.get('/batch/tasks/:taskId', async (req, res) => {
  const task = await getAsyncTask(req.params.taskId);
  success(res, task);
});
```

```sql
SELECT 
  c.id,
  c.contract_no,
  c.received AS contract_received,
  COALESCE(SUM(o.received_amount), 0) AS orders_received
FROM contracts c
LEFT JOIN orders o ON o.contract_id = c.id
GROUP BY c.id
HAVING ABS(contract_received - orders_received) > 0.01;

-- 验证项目金额是否与合同汇总一致

  p.id,
  p.name,
  p.received AS project_received,

GROUP BY p.id
```

## 七、总结

本次代码审查发现了**批量删除操作后数据不一致**的核心问题，主要原因是金额重算逻辑缺少合同和项目同步步骤。这导致：

1. 数据库中存在大量不一致的"脏数据"
2. 查询时需要处理这些脏数据，性能下降
3. 权限过滤遇到异常数据，返回403错误
4. 长时间查询导致前端超时

**修复建议：**
按照优先级修复上述BUG，重点关注数据同步逻辑的完整性和查询性能优化。

**预期效果：**
修复后，批量删除操作将正确更新所有关联数据的金额，查询性能将显著提升，不再出现超时和403错误。
